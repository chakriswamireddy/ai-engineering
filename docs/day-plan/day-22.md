# Day 22 — Agent Evaluation

## Objective

Twenty-one days built a machine that reads (Days 6–10), acts (11–12), survives failure (13), computes (14–15), plans (16), remembers (17–18), decides its own architecture (19), judges its own work (20), and — since Day 21 — *measures its own retrieval*. Day 21 ran the retriever through the court and produced the RAG benchmark: R1–R9 on the golden set, at 0 chats, with the refusal gate's oldest question settled by its own numbers. The curriculum now turns the same court on the same golden set and says its shortest objective yet, three words: **"Measure agent behavior."** Its track list is the eight columns Day 20 printed an owner on and Day 21 handed to "the bench's sibling" — **task success, tool selection, tool argument correctness, number of steps, unnecessary calls, failure recovery, cost, latency** — and its deliverable is the thing Days 11–13 built and never once measured as a machine: **the agent benchmark.** Day 22's opening census is the honest one: six of the eight columns already exist *as trace fields* — `run_agent`'s dict carries termination (`answer`/`max_steps`/`budget`/`gave_up`), `tool_steps`, the per-step `calls` rows with `args_valid`, the registry's rejection counts, the refusals, the ledger's chats/embeds/tokens/cost, and Day 13's `tool_timeouts` and `elapsed_ms` — so the day's genuine build is exactly two: **unnecessary calls, which have never been defined, and failure recovery, which has never been a rate.** The ratio the series keeps meeting is the same one Day 21 found: the metrics everybody could compute stayed hand-quoted for fifteen days, and the two nobody could compute are the ones a pre-registered golden set finally makes writable.

Day 22's first principle is the behavioral translation of Day 20's court rule: **a behavioral verdict is only as honest as the trace the behavior left, and the judge reads that trace and never re-executes the run.** An agent is the one object in this series that *acts*, so its evidence is not a retrieval list but a transcript of choices — and the judge's cardinal error would be to re-run the agent to "check" it: a second execution is a second production run, a second bill, and a verdict on a run the judge was never handed (Day 20's rule, now aimed at the thing that moves). To that Day 22 adds its own spine: **the two columns that never had arithmetic are the ones the golden set finally makes writable.** Unnecessary calls is the precision of the agent bench — it needs a notion of *necessary* that only a pre-registered call envelope can supply — so Day 22 mints `necessary_calls` into the golden rows (the minimal call set a correct answer must have made, written from task structure *before* any run, hash-pinned, rejectable if it leaks), and grades an unnecessary call exactly where the trace makes it mechanical: a repeat fingerprint with no new evidence (Day 13's `no_progress`, now a column), a call that added no evidence id the union did not already hold, or a call whose evidence no later step and no answer ever cited — with the residue (a call that plausibly shaped prose but is uncited) parked as `undecided`, never silently passed. Failure recovery is the inverse: the trace has recorded rejections, refusals, `error_kind`s, and timeouts since Day 13, but nobody ever turned "the run kept going" into a number — Day 22 defines **recovery = a failure event followed by a step that progressed (a Δ in evidence, or a grounded answer), never by a fabrication**, and reports the rate per row. And the day's counterweight is the series' oldest voice once more: **the agent bench is a fixture with a control — AB9 — because a bench that changes a single agent run is a judge in the answer path**, the P9/S9/M8/G9/V9/R9 reflex pointing at the loop itself.

Second census, the one that decides the day's table: **cost and latency are already columns, not builds.** The ledger has billed every chat, every embed, and their tokens since Day 4; latency has a home in Day 13's `elapsed_ms` and `tool_timeouts`. Day 22's real design problem is where the object differs from the retriever: **the agent's choices are stochastic where the retriever's were deterministic.** Day 21 measured a pure function of the trace — the same store, same K, same numbers, forever. An agent run is an outcome, not an identity; the same golden row run twice can take different steps, so the agent bench must grade the *distribution's* evidence — the trace it walked this time — and the report must say which row was graded against which scripted stub and which real-model run, never pretending one sample proves the agent. The day's structure is therefore Day 21's exactly, carried across the seam the earlier notes drew: **the RAG benchmark made the retriever account for its retrieval; the agent benchmark makes the agent account for its behavior** — tool selection measured as Day 11 always meant (per-step recall@1, now a column), argument correctness measured as Day 11's registry always decided it (`args_valid`, plus membership of the pre-registered `necessary_calls` payloads), task success re-used from Day 21's claim-coverage instead of re-invented (the golden `claims[]` graded against the run's own transcript, `must_not_assert` still the only automatic fail), steps measured against a pre-registered `expected_steps` envelope, cost and latency priced per row — and the day's headline, the oldest open `PENDING` in the agent line: **will a real model pick the right tool per step, correct its arguments, avoid unnecessary calls, and recover** — measured on the same golden set Day 21 put the retriever on, in the stub world for free and in the real world at a price the ledger already knows how to bill.

## Duties Outline

### 1. Learn: The Loaded Objective — "Measure Agent Behavior" and the Eight Columns (45 min)

- [ ] Parse the day's three-word objective as discipline, not mood: **"measure agent behavior"** bans the only evidence the series had for "the agent is good" — Day 12's stub fixtures and a human watching one run — and it bans it *structurally*: the day is not a report on a run, it is a **benchmark**, a fixed ship with a pinned baseline and a reproducibility contract, so that Days 23–30 can ask "did the agent improve?" and receive columns, not a re-read transcript. Day 21 made the retrieval verdict a machine's output on fixed rows; Day 22 makes the *behavior* verdict one.
- [ ] Inventory the eight curriculum columns against the code before deciding anything is a build, because the day is smaller than it looks: **task success** has its ingredients already (`termination_reason`, `cited ⊆ retrieved`, and Day 21's claim-coverage over the transcript); **tool selection** is Day 11's per-step recall@1, measured since Day 12's §8 table and never printed as a column; **tool argument correctness** is Day 11's `args_valid` and rejection-names-the-field, in every step row; **number of steps** is `tool_steps` and the termination quality; **cost** is the ledger's records delta (chats, embeds, tokens, USD); **latency** is Day 13's `elapsed_ms` and `tool_timeouts`, awaiting attribution. The two genuinely empty: **unnecessary calls** (no definition has ever been written) and **failure recovery** (rejections/refusals/errors/timeouts are recorded, never a rate).
- [ ] Pre-commit the day's split, unchanged from every day since Day 7: **the arithmetic columns are `MECH`** — task-success memberships, TSR@1, `args_valid`, step counts, the unnecessary-call rules, the recovery rate, cost, and latency all read the run's trace and nothing else, byte-reproducible; **the meaning cells are the semantic residue** — whether the answer's claims are actually true (Day 21's lane, re-used verbatim), whether a recovery was a *good* recovery rather than merely a progressing one, and whether an uncited call was defensible — each parked `PENDING` with an owner, never silently passed.
- [ ] Pre-commit the day's three invariants before any build: **(a) `judged ⊆ pre-registered`** carried from Days 20–21, extended to the new field — `necessary_calls` is written before any run and graded under the same content hash (an envelope widened after the run to flatter efficiency is the curve-fit, in its call form); **(b) the judge must not re-execute** — the bench reads the run's `steps`/`tool_ledger`/`ledger` and never calls `chat` again, or it grades a run nobody gave it; **(c) AB9** — bench off ≡ days-without, the V9/R9 reflex on the loop surface, because a benchmark that improves a single agent run is a fixer in a lab coat.
- [ ] Pre-commit the sampling honesty the object forces: **a run is an outcome, not an identity** — the same golden row may walk different steps on different runs, so the bench grades the trace it was handed and the report labels the world (`stub` vs `real`) and the run id; under the stub the mechanics are deterministic by script, and the real-model column is the *distribution's* first sample, reported as one sample, never as the truth.

### 2. Learn: The Three Columns That Already Lived in the Trace — Task Success, Tool Selection, Argument Correctness (45 min)

- [ ] Learn **task success** as the series already owns it, neuron by neuron: the golden set's `expected_answer.claims[]` + `must_not_assert[]` are Day 20's oracle-derivable facts, and Day 21's claim-coverage graded them against the run's own evidence — Day 22 carries the lane across the transcript unchanged (`coverage` over `claims[]`, a `must_not` hit always a fail). The one genuinely-agile addition is the **termination** clause: an E-family row succeeds only if the run refused (`termination` reported, gate or model), an answerable row only if it actually answered — `termination_reason == expected_termination` is `MECH`, pre-registered per row, and the five-term (`answer`/`max_steps`/`budget`/`gave_up`) is exactly the vocabulary that makes it a column, Day 12's contract issued by a machine.
- [ ] Learn **tool selection** as the day's loaded old promise: Day 11's §8 wrote "the `tool chosen vs expected action` column is now a **per-step** recall@1" and every day since hand-quoted it; Day 22 prints it. TSR@1 = the fraction of steps whose chosen tool is a member of the row's pre-registered `expected_tools` — membership, not a script — with the two sharp edges Day 13 already named: a step that picks a tool *outside* the set is a **tool miss**, and a required tool never called is a **tool omission** (`tool coverage = |expected_tools ∩ called| / |expected_tools|`), and the miss's owner is still the **schema description** the chooser read (Day 13's F1 attribution, kept verbatim).
- [ ] Learn **tool argument correctness** as Day 11's registry plus one pre-registered extension: `args_valid` is already the rejection verdict (`missing`, `unknown`, wrong type, wrong enum — the message names the field, which is what self-correction corrects against); Day 22's addition is *payload membership* — for each `necessary_calls` entry the golden row pre-registers the expected arguments, and a call that parsed but deviates from the expected payload is an **argument deviation** (correct shape, wrong target), the semantic half owned by the same lane that owns Day 21's citation support, because "syntactically valid, semantically wrong" is byte-identical in the trace to "correct."
- [ ] Pre-commit the honest edge-cases: **empty `expected_tools`** (E-family refusals) → TSR@1 is `n/a`, never 0.0 (0.0 would grade "refused to choose, pass"); **a scripted adversarial row's exact sequence** → order is checked only where the row pre-registers it (the stub's scripted scenarios do; free real runs may not); **a deferred call** (Day 11's cap) counts as *chosen, not executed* — the bench records it, never grades it as a miss.

### 3. Learn: The Two Genuinely New Columns — Unnecessary Calls and Failure Recovery, plus Cost and Latency (45 min)

- [ ] Learn **unnecessary calls** as the precision of the agent bench, and why nobody hand-counted it first: asking "was this call necessary?" needs a notion of *necessary* the transcript cannot supply by itself — Day 13's fingerprint catches repeats, but "the agent called a tool whose evidence it never used" was a paragraph in a report, never a column. The series' answer, in one sentence: **the golden set is the necessity oracle.** Each answerable golden row gains `necessary_calls` (the minimal call set a correct answer must have made, minted pre-run from task structure under the same discipline as `relevant_also`), and an *unnecessary* call is graded exactly where the trace makes it mechanical: **(U1) a duplicate fingerprint** — same tool, normalized args, no Δ (Day 13's `no_progress`, now a unit); **(U2) no Δ-evidence** — the call's evidence ids are all already in the union of earlier steps, and it produced no data record; **(U3) never-cited** — its evidence is cited by no later step and no final answer. Efficiency = `1 − unnecessary/total`, `necessary ⊆ made` is call-coverage, and a call that *looks* unnecessary but might have shaped the answer's prose is **`undecided`**, recorded with an owner, never silently added to either column — the same honesty Day 21 applied to undeducible claims, in call form.
- [ ] Learn **failure recovery** as the inverse: the trace has recorded every failure event since Day 13 — `rejections` (bad args), `observed_refusals` (gate refusals), `error_kind`s (`timeout`/`tool_error`), `tool_timeouts` — and nobody ever turned "the run kept going" into a rate. Day 22's definition, pre-registered as hard as the call envelope: a failure is **recovered** when a later step **progresses** — its evidence union grows or the run terminates with a grounded answer — and **never recovered by fabrication** (`fabricated` must stay `false`, the F-series invariant now a column). Report `recovery_rate = recovered / failures`, `gave_up` as the honest zero, and the *cost* of recovery (the extra steps and tokens a recovery spent) next to the rate — because "recovered in one extra step" and "recovered after burning three steps" are different verdicts wearing the same `recovered` label.
- [ ] Learn **cost and latency** as columns the series already owns, priced not built: **cost** is the ledger's delta from the run (`chats`, `embeds`, `tokens`, `cost_usd` — bills per step since Day 4, the worst case `max_steps × 2 + 1`), and the A-report writes it per row and per world (the stub costs nothing; the real model costs what it costs); **latency** is Day 13's `elapsed_ms` plus `tool_timeouts`, and the day's one genuine addition is **attribution** — which step, and which tool within it, owned the wall-clock — because "the agent was slow" is not a verdict until it says who was slow, and the full attribution of a graded pipeline is Day 23's seam, named not built.
- [ ] Pre-commit the negatives with owners before the build: **observability of the graded pipeline** (per-request model/retrieval/tool/answer tracing) is **Day 23's** trace; **prompt versioning** is Day 23's; **judge poisoning** (an agent tuned to pass this grader) is **Day 25's** seam; **real data resolvers** and their real timeouts are **Day 14's**; **distributed, correlation-id tracing** is **Day 24's**; and the **fully-golden raw transcript** stays named, not built — the claims-and-calls form is the replacement, exactly as Day 20 said.

### 4. Design: The Agent Benchmark — Day 21's Court, the Agent on the Stand (30 min)

- [ ] Design Day 22 as both series-reads promised: Day 21's court, the machine that acts on it. The agent benchmark is Day 21's harness plus a behavior layer plus a pinned baseline — nothing new in the answer path:

- [ ] Design decision #1 — **six of the eight metrics exist; unnecessary calls and recovery are the build**: TSR@1/args/steps/cost/latency columns read `run_agent`'s dict verbatim; the work is (a) minting `necessary_calls` into the golden YAML under the same oracle-discipline as `relevant_also` (pre-registered from task structure, rejectable if it leaks), and (b) defining the unnecessary-call rules (U1/U2/U3) and the recovery definition (progress-after-failure, never a fabrication) *before* any run, under the day's hash, so efficiency and recovery cannot be retrodicted — Day 21's `relevant_also` discipline, wearing a call ledger.
- [ ] Design decision #2 — **the judge reads the run's trace and never re-executes it**: every column is a pure function of `run_agent`'s returned dict (`steps`, `tool_ledger`, `ledger`, `termination_reason`, `fabricated`, `elapsed_ms`) — the bench adds no chat call anywhere; the only billable cell in the whole day is the flagged residue lane (Day 21's, off by default), and it never flips a `MECH` verdict (Day 20's `deterministic_verdict` rule, carried verbatim across the seam).
- [ ] Design decision #3 — **the two worlds, one harness**: the **stub world** proves the mechanics — scripted multi-step scenarios make AB2–AB8 reproducible offline at 0 tokens, exactly as A1–A8 and F1–F9 did; the **real-model world** delivers the verdicts — the same golden rows run through the real gateway on the chosen store, and the report *labels* which world each row came from, because a stub verdict and a real verdict are different facts wearing the same column header. The code-store rows (CA1–CE1) run on the stub's mechanism proof until the real Saleor code store lands — Day 10's `PENDING`, written so the same rows re-run the day it does.
- [ ] Design decision #4 — **the A-bench inherits Day 21's real-store debit**: the retriever behind `search_saleor_docs` still leaks (7 of 9 doc rows at top-8, pinned on Day 9 and reproduced on Day 21), so the agent may choose the *right* tool and still lose because the tool's store leaked — the A-report's attribution rule is Day 7's isolation: a wrong answer whose evidence never reached the tool is a **retrieval debit (Day 8's backlog)**, not an agent fail; the tool fetched it and the agent ignored it is an **agent/description debit**; and the report says which, never a blend.
- [ ] Pre-commit the day's negatives with owners, not wishes: **agent-to-agent hand-off and topology** (Day 19's B) stays gated on G1's measured row; **observability** is Day 23's; **judge poisoning** stays Day 25's seam; the **fully-golden raw transcript** stays named, not built — the claims-and-calls form is the replacement, and the A-bench grades exactly that form.

### 8. Test: The AB-Fixtures (AB1…AB9) and the Control (1 hour)
