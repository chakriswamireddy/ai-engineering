## Cost (the price of measurement vs the price of being measured)

- the agent bench (all `MECH` columns): **0 chats** — arithmetic over one run dict;
- the **stub world** bills nothing (the in-process scripted gateway); the **real world** bills exactly what `run_agent` billed;
- the run's worst case is `max_steps × 2 + 1` chats; the ``undecided`` residue lane is Day 21's (off by default) and never flips a `MECH` verdict.

**The `PENDING` line, owned:** claim truth & support-in-meaning are Day 21's lanes (re-used); good-recovery and defensible-uncited calls are Day 22's residue (off by default); observability (why that latency, which model, which prompt) is **Day 23's** trace; distributed tracing is **Day 24's**; judge poisoning is **Day 25's**.

## The two worlds, one harness

The A-bench is Day 20's harness plus a behaviour layer — nothing new in the answer
path — and it runs in two labelled worlds:

- **the stub world** (rows above) — Day 20's in-process scripted gateway, one
  competent turn per golden row: it *proves the mechanics* (AB1–AB9) at **$0**;
- **the real world** (`python tools/bench_agent.py --real`) — the `.env` gateway
  on the real stores: it *delivers the verdicts*. This closes the oldest open
  `PENDING` in the agent line — **Day 11's real-model tool choice** and **Day 12's
  "does a real model drive multi-step well"** — measured here as columns, not a
  re-read transcript. A real row is a **sample** (a run is an outcome, not an
  identity), so the report labels the world and never prints one stub verdict as
  the agent's truth. The code rows (CA1–CE1) run on the stub's mechanism proof
  until Day 10's quota-blocked `data/code_store.json` lands, and are written to
  re-run the day it does.

## The pinned baseline (Day 12/13's stub behaviour as the floor)

`data/agent-baseline.json` pins the stub A-report — per row: the exit, the step
count, `TSR@1`, the unnecessary count, and the recovery rate. It is the floor
Days 23–30 measure "did the agent improve?" against, exactly as
`data/bench-baseline.json` is for retrieval. Both are `MECH` and reproducible.

## Attribution (Day 7's isolation, never a blend)

The A-bench refuses to let the agent's failures hide under the retriever's or the
retriever's under the agent's. When a row fails:

- the tool **never fetched** the expected evidence → **retrieval debit** (Day 8's
  backlog — Day 21 reproduced 7-of-9 doc rows leaking at top-8);
- the tool fetched it and the agent **ignored** it → **description/agent debit**
  (Day 13's F1 rule: the metadata written for a chooser is the first suspect);
- a required tool never called → a **tool omission**; a wrong tool chosen → a
  **tool miss**, owner `description`.

`agent_bench.attribute_failure` computes the first applicable owner, so a real-row
verdict names *where* it failed, not merely *that* it did.

## The `MECH` verdict, and the honest `n/a`

Three columns carry the day. **The `MECH` verdict on every row** — the same run
dict graded twice is the same row (V2's rule, carried). **The `n/a` cells
honored** — E-family `TSR@1` and precision-style cells are `n/a`, never `0.0`,
because `0.0` would grade "refused to choose, pass". **The `PENDING`s with
owners** — claim truth (Day 21's lane, re-used), support-in-meaning (Day 21's
K-row half), good-recovery judgment, and defensible-uncited calls (Day 22's new
residue) all sit in the flagged lane, off by default, priced before spent.
