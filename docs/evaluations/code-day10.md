## Negatives (honest, with owners)

1. **The stub τ does not *separate* E from answerable — and neither did Day 9's
   real run.** On this 14-symbol stub the answerable top-1s run **0.636–0.863**
   and CE1's is **0.703** — they overlap, so no single τ cleanly refuses E
   without also scoring CC1's answer below it. τ=0.75 is a *demo choice* to
   exercise the refusal path, not a calibration. On the real corpus Day 9
   already recorded fused E top-1s of 0.854/0.874 overlapping the answerable
   family: **the refusal signal must move semantic — Day 21 owns τ.** (The stub
   repeats Day 9's finding on a different corpus, which is the point.)
2. **Interface-only embedding's blind spot is real and unmeasured.** A symbol
   whose behavior matches but whose name/docstring don't will be missed. A
   body-embedding sweep is the `PENDING` knob; the stub cannot resolve it
   because its embedder is meaning-free. Owner: Day 21.
3. **The static imports map under-supports cross-module questions.** CB1/CB2
   pass because their answer symbols are directly retrievable, not because the
   *graph* was walked. Finding the map is Day 10; walking it is Day 12/16.
4. **The real Saleor build is quota-blocked (2026-09-23).** The clone is present
   (`corpus_code/saleor/`, 4,323 `.py` files → **29,156 symbols** with the fixed
   extractor) and the build was attempted for real; it hit Cloudflare Workers
   AI's **daily free allocation of 10,000 neurons** at ~16k symbols (`429
   AiError … used up your daily free allocation`). The extractor's file-level
   guard was fixed first (below), so all eight fixture symbols now resolve in the
   real tree; the *embedding* budget is the remaining wall. See "Real corpus —
   2026-09-23" for the numbers and the one-command resume.
5. **`Δrank +0` on four of six rows** — the stub's 14 symbols are too few for the
   reranker to reorder much; the mechanism is proved by CA1 (+1) and by
   `test_day10.py`'s hand-built cases, not by volume.

## Real corpus — 2026-09-23

The real Saleor tree was ingested for real and the build was attempted. Two
extractor defects surfaced *at ingest* (exactly where §7 says the exact paths get
confirmed) and were fixed before the build:

- **The size bound was per *file*, not per *chunk*.** `>40 symbols or >40 KB →
  window the whole file` routed **128 legitimate modules** to the windowed path —
  including `saleor/checkout/complete_checkout.py` (71 KB), the file whose
  `complete_checkout` is CA1's answer, and `saleor/graphql/checkout/types.py`
  (54 KB), the file whose `Checkout` is CC1's. The corpus could not cite its own
  fixtures. The bound is now `MAX_CHUNK_CHARS` per chunk, so a large module keeps
  one chunk per symbol and only an individual oversized symbol is windowed.
- **Nested classes were emitted with bare names.** Every Django `class Meta`
  collapsed to `module#Meta` — **233 duplicate `doc_id`s / 952 chunks**, which
  breaks the citation-filter-dedup key. Nested classes now carry their scope
  (`User.Meta`); collisions drop to **12 ids / 23 chunks**, all genuine
  `@overload` definitions that share a name by construction.

Result: **29,156 symbols / 29,133 unique `doc_id`s** over 4,323 files, and all
eight pre-registered fixture symbols resolve in the real tree (`complete_checkout`,
`CheckoutComplete`, `create_order_from_checkout`, `process_payment`,
`WebhookEventAsyncType`, both `Checkout` senses, and the real CD1 test).

The build then hit Cloudflare Workers AI's **daily free allocation of 10,000
neurons** at ~16k symbols (`429 … used up your daily free allocation of 10,000
neurons`). The runner-up provider (OpenRouter `nemotron-3-embed-1b`, dim **2048**)
is a *different* embedding space, so the builder was hardened to **stop and
preserve** the partial store on a mid-build model switch rather than wipe it.

## Cost shape (build vs run)

| Axis | Doc corpus | Code corpus |
|---|---|---|
| retrieval unit | chunk (200/40 window) | symbol (AST-bound) |
| expected evidence | `doc_id#heading` | `module#Symbol` |
| **build** embeds | ~1 per chunk | **one per symbol** (tens of thousands for Saleor) |
| **run** cost | 1 embed + 1 chat | 1 embed + 1 chat — **same** |
| added ledger lines | — | **zero** (rerank/MMR/dedup are arithmetic) |

> Δrank is the best-pre-ranked expected symbol's pre→post slot across the rerank
> seam. The code corpus adds a corpus, not a subsystem: `retrieve`/`rerank`/
> `mmr`/`dedup`/`build_context`/`/rag` are unchanged; only ingestion (AST),
> metadata (`symbol/kind/signature/imports`), and vocabulary (`code_tokens`,
> `CODE_REWRITES`) are code-specific.
