## Pre-registration (the hash mechanics)

- `ai_os/golden.yaml` is the commitment: the five fields written **before** any run, pinned by a sha256 content hash over every graded field (evidence, answer, tools, failure category, judge-hunting probes).
- pinned hash `94d343ad20c94dab…` == computed `94d343ad20c94dab…`; `registered_at: 2026-09-28`.
- The harness **refuses to grade under a stale hash** (`IntegrityError`, V1/V8): a row patched after the run came up short is an integrity failure, not a run. Re-pin only for an intended edit: `python ai_os/eval_dataset.py --pin ai_os/golden.yaml`.
- A run that started before its row's registration is **flagged** (`ai_os.eval_dataset.rows_registered_before`) — the anti-curve-fit fixture.

## The regression gate (Rule 2's ratchet)

```bash
python tools/regress_all.py          # doc nine + code six + every day suite (Days 7–19) + golden rows
python tools/regress_all.py --fast   # fixtures + golden rows only
```
Improvement is measured on the golden set; **preservation** is measured here. Every row must come back *exactly as green*; a row a run cannot reproduce is a gate bug to fix, never a fixture to weaken.
